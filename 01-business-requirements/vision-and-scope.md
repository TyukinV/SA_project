## 1. Бизнес-возможность 

### Проблема 
На сегодняшний день более 60% небольших отелей (до 50 номеров) управляют бронированиями с помощью **Excel-таблиц, бумажных журналов или устаревших кассовых систем**.
Это приводит к:

- **Критическим финансовым потерям** из-за *овербукинга* (продажа одного номера двум клиентам), когда управляющий забывает обновить статус в таблице.
- **Сложности с динамическим ценообразованием:** Вручную нереально уследить за спросом на выходные и праздники, чтобы поднять цену, и наоборот — вовремя опустить при низкой загрузке.
- **Потере клиентов:** Гости не могут гарантированно подтвердить бронь без предоплаты, а менеджеры тратят до 20 минут на один звонок для уточнения наличия номеров.

### Возможность 
Создать легковесную, интуитивную систему, которая **исключает человеческий фактор** при управлении статусами номеров и автоматически пересчитывает цены на основе загруженности отеля.

## 2. Видение продукта 

> **Для** управляющих и администраторов отелей, которые устали от хаоса вручную,
> Наша система — это **единое окно управления номерным фондом**,
> Которая **автоматически синхронизирует статусы номеров в реальном времени и предоставляет гибкие инструменты для настройки цен по правилам (сезон, выходные, длительность проживания),
В отличие от Excel и бумажных**,
> В отличие от Excel и бумажных журналов,
> Наш продукт гарантирует **100% исключение двойных продаж** и сокращает время подтверждения бронирования до **30 секунд** и закладывает основу для автоматического ценообразования в будущих релизах.

## 3. Ключевые стейкхолдеры 

Для успешного сбора требований я выделил 4 ключевые роли:

| Стейкхолдер | Интересы и ожидания | Боли |
| :--- | :--- | :--- |
| **Гость (Клиент)** | Быстро найти номер по датам, оплатить онлайн, получить гарантию заезда. | Сложные формы, зависшие сайты, отсутствие подтверждения на почту. |
| **Администратор отеля** (Ресепшн) | Управлять заездами/выездами, видеть актуальный статус уборки номеров. | Путаница в статусах, нет мобильности (привязан к стойке). |
| **Менеджер продаж** | Видеть статистику загрузки, корректировать цены, работать с корпоративными заявками. | Нет аналитики, не видят динамику спроса. |
| **Владелец отеля** | Максимизировать прибыль, видеть отчеты по выручке. | Не доверяет отчетам из Excel, нет прозрачности. |

## 4. Границы проекта 

###  Что входит в MVP (Версия 1.0)
Критически важные функции, без которых система нежизнеспособна:

1. **Модуль поиска и отображения:** Фильтрация номеров по датам заезда/выезда, количеству гостей, цене.
2. **Модуль онлайн-бронирования:** Создание брони с блокировкой номера на время оплаты (15 минут).
3. **Интеграция с платежным шлюзом:** Прием предоплаты (Stripe / ЮKassa). Без этого бронь не «закрепляется».
4. **Личный кабинет администратора:** Управление статусами номеров (Чисто/Грязно/На ремонте).
5. **Автоматическая рассылка:** Email-уведомления клиенту о статусе бронирования.
6. **Базовая модель данных:** Сущности: Номер, Гость, Бронирование, Платеж.

###  Что НЕ входит в MVP 

- **Мобильное приложение для гостей:** MVP реализуется только в виде адаптивного Web-интерфейса.
- **Интеграция с POS-терминалами** (фискальные регистраторы) для оплаты на ресепшн.
- **Модуль управления рестораном и дополнительными услугами** (спа, трансфер).
- **Интеграция с системами умного дома** (смарт-замки, автоматическое заселение по QR-коду).
- **Поддержка нескольких языков и валют** на старте (ориентация только на локальный рынок).
- **Исторический импорт данных** из старых Excel-журналов (отель начинает вести базу «с нуля»).

## 5. Функциональные области 

Разбивка по модулям для дальнейшей детализации в ЧТЗ:

| Модуль | Ключевые функции (Epics) |
| :--- | :--- |
| **Управление номерами** | CRUD номеров, управление характеристиками (этаж, вид из окна, вместимость), переключение физического статуса (Доступен / На уборке / На ремонте) — занятость по датам управляется через календарь. |
| **Календарь и цены** | Визуальный календарь загрузки, установка базовых цен, наценка за сезон/выходные, минимальная длина проживания (Min Stay). |
| **Поток бронирования** | Блокировка номера, обработка оплаты, автоматическая отмена при таймауте, ручная отмена или изменение дат. |
| **Управление гостями** | Регистрация гостей, история предыдущих заездов, черный список (при нарушении правил). |
| **Отчеты и Аналитика** | Отчет по загрузке (Occupancy Rate), отчет по выручке (RevPAR), список No-Show (незаезд). |

## 6. Ограничения и допущения 

### Архитектурные ограничения
- Система должна быть доступна 24/7 с временем восстановления (RTO) менее 4 часов.
- Все операции по изменению статуса бронирования должны выполняться в рамках транзакций базы данных с уровнем изоляции READ COMMITTED (или выше).

### Бизнес-ограничения
- Максимальное количество номеров в одном отеле, поддерживаемое MVP — 100.
- Платежный шлюз выбран заранее (условно), интеграция с другими шлюзами не предусмотрена в релизе 1.0.

### Допущения 
- Предполагается, что у администраторов отеля есть стабильный доступ к высокоскоростному интернету.
- Предполагается, что все пользователи имеют современные браузеры (Chrome/Firefox последних версий).

## 7. Критерии успеха 

Для проверки эффективности внедрения мы будем отслеживать метрики (это добавляет веса вашему анализу):

1. **Снижение овербукинга до 0%** — полное исключение инцидентов двойной продажи.
2. **Время обработки бронирования** — сокращение с 15 минут (по телефону) до 2 минут (онлайн).
3. **Увеличение Revenue (выручки) на 10-15%** за счёт внедрения гибких правил ценообразования (сезонные коэффициенты, наценка за выходные, минимальная длина проживания), которые позволяют менеджеру оперативно реагировать на спрос. Автоматическая оптимизация цен на основе загрузки отеля запланирована на последующие релизы
4. **CSI (Удовлетворенность гостей):** Увеличение положительных отзывов о процессе заселения на 20%.
