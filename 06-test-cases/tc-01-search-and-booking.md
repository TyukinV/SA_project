## 1. Назначение

Проверить сквозной сценарий гостя: **поиск доступного номера → создание брони с блокировкой**. Это критический путь системы, без которого невозможны ни оплата, ни последующие сценарии.

**Цель теста:** убедиться, что система корректно находит свободные номера, создаёт бронь со статусом `PENDING`, блокирует номер в календаре на 15 минут и возвращает `booking_id` для последующей оплаты.

---

## 2. Предусловия

| Условие | Значение |
| :--- | :--- |
| В БД | 10 номеров: 5 STANDARD, 3 DELUXE, 2 SUITE |
| Номер №101 | STANDARD, capacity = 2, base_price = 5000 RUB/ночь |
| Календарь | Номер №101 свободен на 10–13 августа 2026 |
| Активные брони | Отсутствуют на выбранные даты |
| Гость | Находится на странице поиска, не авторизован |
| Backend | Доступен, БД подключена, Scheduler запущен |

---

## 3. Сценарии

### Сценарий 1: Успешный поиск доступных номеров

```gherkin
Функция: Поиск доступных номеров
  Сценарий: Гость ищет номер на свободные даты
    Дано гость находится на странице поиска
    И указал даты: заезд "2026-08-10", выезд "2026-08-13"
    И количество гостей = 2
    Когда гость нажимает "Найти"
    Тогда система возвращает список доступных номеров
    И для каждого номера указаны поля:
      | Поле                 | Значение |
      | room_id              | 101      |
      | room_number          | "101"    |
      | room_type            | STANDARD |
      | capacity             | 2        |
      | base_price_per_night | 500000   |
      | total_price          | 1500000  |
      | currency             | RUB      |
      | available            | true     |
    И в списке только номера с capacity >= 2
    И время отклика API < 500 мс
```

---

### Сценарий 2: Успешное создание брони

```gherkin
Функция: Создание бронирования
  Сценарий: Гость бронирует выбранный номер
    Дано гость выбрал номер №101 из результатов поиска
    И открыл форму бронирования
    Когда гость заполняет контактные данные:
      | Поле    | Значение         |
      | Имя     | Иван Петров      |
      | Email   | ivan@example.com |
      | Телефон | +79991234567     |
    И нажимает "Забронировать"
    Тогда система создаёт бронь со статусом "PENDING"
    И устанавливает expires_at = now() + 15 минут
    И блокирует номер №101 в календаре на даты:
      | calendar_date | is_available |
      | 2026-08-10    | false        |
      | 2026-08-11    | false        |
      | 2026-08-12    | false        |
    И возвращает booking_id (UUID)
    И возвращает payment_url для оплаты
    И перенаправляет гостя на страницу оплаты
    И записывает событие в booking_events:
      | old_status | new_status | changed_by |
      | NULL       | PENDING    | guest_id   |
```

---

### Сценарий 3: Проверка блокировки календаря

```gherkin
Функция: Блокировка календаря
  Сценарий: После создания брони номер недоступен для других
    Дано бронь создана на номер №101, даты 10–13 августа
    Когда другой гость ищет номер на те же даты
    Тогда номер №101 отсутствует в результатах поиска
    И в inventory_calendar для номера №101 на 10, 11, 12 августа:
      | Поле         | Значение |
      | is_available | false    |
      | booking_id   | 123      |
```

---

### Сценарий 4: Ошибка валидации email

```gherkin
Функция: Валидация контактных данных
  Сценарий: Некорректный формат email
    Дано гость заполнил форму бронирования
    И указал email "ivan@invalid"
    Когда гость нажимает "Забронировать"
    Тогда система возвращает ошибку 400 Bad Request
    И сообщение: "Некорректный формат email"
    И бронь НЕ создаётся
    И календарь НЕ блокируется
```

---

### Сценарий 5: Некорректные даты (выезд раньше заезда)

```gherkin
Функция: Валидация дат
  Сценарий: Дата выезда раньше даты заезда
    Когда гость указывает заезд = "2026-09-10", выезд = "2026-09-08"
    Тогда система возвращает ошибку 400 Bad Request
    И сообщение: "Дата выезда должна быть позже даты заезда"
    И кнопка "Найти" неактивна
```

---

### Сценарий 6: Дата заезда в прошлом

```gherkin
Функция: Валидация дат
  Сценарий: Заезд в прошлом
    Дано текущая дата = "2026-09-01"
    Когда гость указывает заезд = "2026-08-30"
    Тогда система возвращает ошибку 400 Bad Request
    И сообщение: "Дата заезда не может быть в прошлом"
```

---

### Сценарий 7: Превышение количества гостей

```gherkin
Функция: Валидация вместимости
  Сценарий: Гостей больше, чем вмещает номер
    Дано номер №101 (STANDARD) вмещает 2 гостей
    Когда гость указывает количество гостей = 3
    Тогда номер №101 НЕ появляется в результатах поиска
    И система предлагает номера с capacity >= 3
```

---

### Сценарий 8: Нет доступных номеров

```gherkin
Функция: Обработка пустого результата
  Сценарий: Все номера заняты на выбранные даты
    Дано все 10 номеров забронированы на 10–13 августа 2026
    Когда гость нажимает "Найти"
    Тогда система возвращает пустой список results = []
    И показывает сообщение: "Нет свободных номеров на выбранные даты"
    И предлагает изменить даты
```

---

### Сценарий 9: Изменение цены при повторном поиске

```gherkin
Функция: Актуальность цены
  Сценарий: Менеджер изменил цену между поиском и бронированием
    Дано гость ищет номер №101 и видит цену 5000 RUB/ночь
    Когда менеджер меняет base_price на 5500 RUB
    И гость повторяет поиск
    Тогда система возвращает обновлённую цену 5500 RUB/ночь
    И total_price = 1650000 за 3 ночи
```

## 4. Постусловия

| Состояние | Значение |
| :--- | :--- |
| `bookings` | Запись со статусом `PENDING`, `expires_at = now() + 15 min` |
| `inventory_calendar` | 3 записи с `is_available = false`, `booking_id = 123` |
| `booking_events` | Запись `NULL → PENDING`, `changed_by = guest_id` |
| Гость | Перенаправлен на страницу оплаты, может завершить оплату в течение 15 минут |
| Scheduler | При следующем запуске найдёт бронь, если она не оплачена |

## 7. Критерии приёмки (Definition of Done)

- [ ] Все 9 сценариев проходят на тестовом стенде.
- [ ] Покрытие автотестами ≥ 80% для кода поиска и создания брони.
- [ ] Нагрузочный тест: 1000 RPS на `GET /search` с p95 < 500 мс.
- [ ] Проверено, что `booking_id` возвращается в формате UUID.
- [ ] Проверено, что `expires_at` = `created_at + 15 минут` (не больше, не меньше).
- [ ] Логи содержат `booking_created` с полями `booking_id`, `room_id`, `guest_email`.
